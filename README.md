# بات پست + دکمه شیشه‌ای انتخابی

## چیکار می‌کنه
- ادمین محتوا (متن/عکس/ویدیو/فایل) می‌فرسته → بات می‌پرسه چه دکمه‌هایی (حداکثر ۳ تا) → پست با دکمه‌های inline تو کانال هدف منتشر می‌شه.
- هر دکمه می‌تونه رأی‌گیری باشه (شمارش کلیک، هر کاربر فقط یه بار) یا لینک باشه.
- منوی مدیریت با کیبورد معمولی (نه inline).
- سطح دسترسی: مالک (owner) → ادمین‌ها → کاربران مجاز.
- عضویت اجباری قبل از استفاده از بات و رأی‌دادن.
- دیتابیس: Supabase (Postgres رایگان)، فایل‌ها ذخیره نمی‌شن، فقط `file_id` تلگرام نگه داشته می‌شه.

## محدودیت مهم (باید بدونی)
تلگرام به بات‌ها اجازه نمی‌ده تاریخچه‌ی قدیمی یه کانال رو بخونن — فقط پست‌هایی که *بعد از عضو شدن بات* در کانال منتشر می‌شن قابل دیدنه (`channel_post` update). پس گزینه‌ی «از آخرین پست تا همه‌ی پست‌ها» با توکن ساده‌ی بات ممکن نیست؛ فقط می‌شه پست‌های جدید رو رصد کرد و خودکار دکمه بهشون اضافه کرد (این نسخه‌ی ساده‌ش رو گذاشتم: `/addsource`). برای گرفتن تاریخچه‌ی قدیمی باید با یه اکانت یوزر واقعی (کتابخونه‌ی Telethon یا Pyrogram + API ID/HASH از my.telegram.org) کار کرد که پروژه‌ی جدا و پیچیده‌تریه — اگه لازمش داری بگو تا جدا برات بسازم.

## مراحل راه‌اندازی

### ۱. ساخت بات
با [@BotFather](https://t.me/BotFather) بات بساز و `BOT_TOKEN` رو بگیر.
آیدی عددی خودت رو هم از [@userinfobot](https://t.me/userinfobot) بگیر (`OWNER_ID`).

### ۲. Supabase
1. تو [supabase.com](https://supabase.com) یه پروژه بساز.
2. برو SQL Editor و کل محتوای `schema.sql` رو اجرا کن.
3. از Settings → API مقادیر `Project URL` و `service_role key` رو بردار.

### ۳. گیت‌هاب
این پوشه رو تو یه ریپازیتوری گیت‌هاب push کن.

### ۴. Render
1. یه Web Service جدید از روی ریپازیتوری بساز.
2. Build command: `pip install -r requirements.txt`
3. Start command: `python bot.py`
4. متغیرهای محیطی (Environment) رو طبق `.env.example` پر کن. `WEBHOOK_URL` همون آدرسیه که Render بهت می‌ده (مثلاً `https://your-app.onrender.com`).
5. دیپلوی کن.

### ۴.۱ اضافه کردن ادمین از طریق Render (بدون دستور تو بات)
اگه می‌خوای ادمین‌ها رو مستقیم از پنل رندر مدیریت کنی، نه با دستور `/addadmin`:
1. تو داشبورد Render برو سرویس بات → تب **Environment**.
2. یه متغیر جدید بساز به اسم `ADMIN_IDS`.
3. آیدی عددی هر ادمین (از [@userinfobot](https://t.me/userinfobot)) رو با کاما جدا بنویس، مثلا:
   `ADMIN_IDS=111111111,222222222`
4. Save کن؛ رندر خودش سرویس رو ری‌دیپلوی می‌کنه و از همون لحظه اون آیدی‌ها ادمین حساب می‌شن.
5. برای حذف یه ادمین، آیدیش رو از همین متغیر پاک کن و دوباره Save کن.

این روش جدا از دستور `/addadmin` (که تو دیتابیس Supabase ذخیره می‌کنه) کار می‌کنه؛ هر دو با هم قابل استفاده‌ن. `/admins` هر دو نوع ادمین رو نشون می‌ده (ادمین‌های Render با برچسب `env (Render)` مشخص می‌شن).

### ۵. تست
- تو بات `/start` بزن (خودت owner هستی پس مستقیم رد می‌شی).
- `/panel` رو بزن تا منو باز شه.
- «➕ پست جدید» رو بزن، محتوا بفرست. بعدش بات برای هر دکمه جدا جدا می‌پرسه: اول اسم دکمه، بعد لینکش (اگه لینک نمی‌خواد و فقط رأی‌گیریه بنویس `-`)، و بعد از هر دکمه می‌پرسه دکمه‌ی بعدی هم می‌خوای (تا حداکثر ۳ تا). در آخر بنویس «بفرست».

## دستورات ادمین
| دستور | کار |
|---|---|
| `/panel` | باز کردن منوی ادمین |
| `/newpost` | ساخت پست جدید |
| `/addadmin <id>` | ادمین جدید |
| `/removeadmin <id>` | حذف ادمین (فقط owner) |
| `/admins` | لیست ادمین‌ها |
| `/allow <id>` | دسترسی به کاربر عادی |
| `/disallow <id>` | گرفتن دسترسی |
| `/addforce @channel` | افزودن به عضویت اجباری |
| `/removeforce @channel` | حذف از عضویت اجباری |
| `/forcelist` | لیست عضویت اجباری |
| `/addsource @channel` | رصد پست‌های جدید یه کانال (نه تاریخچه) |

## نکته‌ی مهم درباره‌ی force-join
بات باید تو کانال‌های force-join و کانال هدف (TARGET_CHANNEL) و کانال‌های مبدا (source) به عنوان ادمین اضافه شده باشه، وگرنه `get_chat_member` و ارسال پست خطا می‌ده.
